A Time Series is Worth 64 Words: Long-term Forecasting with Transformers (PatchTST)

  • Authors: Yuqi Nie; Nam H. Nguyen; Phanwadee Sinthong; Jayant Kalagnanam
  • Publication date: 2022-11-27
  • Venue: ICLR 2023
  • Link: https://arxiv.org/abs/2211.14730
  • Github: https://github.com/PatchTST/PatchTST
  • Key innovations / contributions:
    • Patching: segmentation of time series into subseries-level patches which are served as input tokens to Transformer.
    • Channel-independence: each channel contains a single univariate time series that shares the same embedding and Transformer weights across all the series.

iTransformer: Inverted Transformers Are Effective for Time Series Forecasting

  • Authors: Yong Liu; Tengge Hu; Haoran Zhang; Haixu Wu; Shiyu Wang; Lintao Ma; Mingsheng Long
  • Publication date: 2023-10-10
  • Venue: ICLR 2024
  • Link: https://github.com/thuml/iTransformer?tab=readme-ov-file
  • Github: https://github.com/thuml/iTransformer?tab=readme-ov-file
  • Key innovations / contributions:

    • Invert the token dimension: Instead of treating each time step as a token (the usual setup), iTransformer treats each variable/channel as a token. Each token contains that variable’s entire historical window, so the model becomes variate-token based rather than time-token based.

    • Re-align what Attention vs. FFN should learn:

      • Self-attention primarily models cross-variable dependencies (variable–variable interactions).

      • The FFN primarily learns within-variable temporal patterns (nonlinear transformations of each variable’s history).

      This division matches the structure of multivariate time series better than mixing variables inside time-step tokens.

Autoformer: Decomposition Transformers with Auto-Correlation for Long-Term Series Forecasting

  • Authors: Haixu Wu; Jiehui Xu; Jianmin Wang; Mingsheng Long
  • Publication date: 2021-06-24
  • Venue: NeurIPS 2021
  • Link: https://arxiv.org/abs/2106.13008
  • Github: https://github.com/thuml/Autoformer
  • Key innovations / contributions:
    • Autoformer introduces a series decomposition block that splits the input at every layer into:
      • a Trend component (slowly varying, smooth part)
      • a Seasonal component (fluctuating / periodic part)
    • use autoformer mechanism to replace attention, which identifies the most important time delay(lags), frequency decompostion using FFT

ETSformer: Exponential Smoothing Transformers for Time-series Forecasting

  • Authors: Gerald Woo; Chenghao Liu; Doyen Sahoo; Akshat Kumar; Steven C. H. Hoi
  • Publication date: 2022-02-03
  • Venue: Preprint
  • Link: https://arxiv.org/abs/2202.01381
  • Github: https://github.com/azkanaon/etsformer?tab=readme-ov-file
  • Key innovations / contributions:
    • Exponential Smoothing Attention for Growth: AES(V)t=αVt+(1−t)AES(V)t−1AES(V)_{t} = \alpha V_{t}+(1-t)AES(V)_{t-1}AES(V)t​=αVt​+(1−t)AES(V)t−1​
    • Frequency Attention for Seasonality: DFT

Differences between Autoformer and ETSformer:

  • Autoformer: The core idea is moving-average decomposition plus an auto-correlation mechanism that finds the most important lags and aggregates after aligning the sequence by those lags.
  • ETSformer: The core idea is an ETS-style decomposition into level / growth / seasonality, using ESA (Exponential Smoothing Attention) to model the trend (with exponentially decaying weights), FA (Frequency Attention) to model seasonality by selecting top-K dominant frequencies in the frequency domain, and applying growth damping to make multi-step extrapolation more stable.

3 Pretrained / foundation models (general-purpose time-series)

1) General-purpose forecasting TSFMs (Transformer forecasters)

Models primarily pretrained to do forecasting across many datasets/horizons.

  • TimesFM (Google) — decoder-only, large-scale pretraining for strong zero-shot forecasting
  • Moirai (Uni2TS, Salesforce) — “universal” forecasting via large-scale pretraining (cross-frequency, multivariate-friendly)
  • TimeFound — encoder–decoder TS foundation model with multi-resolution patching for zero-shot forecasting (community repo; official repo may differ)
  • TimeGPT-1 (Nixtla) — foundation-style forecasting with emphasis on usability and transfer

2) Tiny / efficient pretrained forecasters

Models optimized for speed, small size, and practical deployment, while still enabling transfer.

  • Tiny Time Mixers (TTMs) — tiny, fast pretraining for strong zero-/few-shot multivariate forecasting (TTM model code is inside this repo)

3) LM-style tokenization / “language of time series”

Models that cast time series into discrete tokens (or similar) and train like language models.

  • Chronos (Amazon) — LM framing (tokenization/quantization) to enable transfer + probabilistic forecasting

4) LLM-repurposing (use an existing LLM as the foundation)

Not a TS foundation model trained from scratch; instead it reprograms an LLM for time series.

  • Time-LLM — patch/token “reprogramming” of pretrained LLMs for forecasting (few-/zero-shot flavor)

5) Multi-task time-series foundation models (forecasting + understanding)

Pretrained for multiple tasks beyond forecasting (classification, imputation, anomaly detection, etc.).

  • MOMENT — open TS foundation family supporting multiple tasks with pretrained backbones
  • UniTS (Harvard MIMs) — unified multi-task model via task/token prompting-style formulation
  • TimesBERT — BERT-style pretraining oriented toward time-series understanding tasks (unofficial implementation repo)

6) Probabilistic / generative TSFMs (explicit uncertainty modeling)

Models designed to produce distributions or samples, not just point forecasts.

  • Lag-Llama — probabilistic forecasting foundation model (explicit lag-based design)
  • TimeDiT — diffusion + transformer for sample-based probabilistic forecasting
  • Sundial — flow-matching style training objective for continuous-valued generative forecasting

7) Scaling via Mixture-of-Experts (MoE)

Models that scale capacity with sparse expert routing for efficiency + specialization.

  • Time-MoE — billion-scale TS foundation model with sparse MoE
  • Moirai-MoE (Uni2TS, Salesforce) — MoE extension aimed at stronger specialization/efficiency in TS pretraining (implemented/released via Uni2TS)

5 Physics-Informed Models

Hamiltonian Neural Networks

  • Authors: Sam Greydanus, Misko Dzamba, Jason Yosinski
  • Publication date: 2019-06-04
  • Venue: NeurIPS 2019
  • Link: https://arxiv.org/pdf/1906.01563
  • Github:
  • Key innovations / contributions:
    • The network outputs a single energy-like function Hθ(q,p)H_\theta(q,p)Hθ​(q,p).
    • The model’s predicted dynamics are hard-constrained to be
      q˙=∂Hθ∂p,p˙=−∂Hθ∂q\dot q = \frac{\partial H_\theta}{\partial p}, \qquad \dot p = -\frac{\partial H_\theta}{\partial q}q˙​=∂p∂Hθ​​,p˙​=−∂q∂Hθ​​
      using automatic differentiation.
    • It builds in physics structure (symplectic / Hamiltonian form), so the learned dynamics tend to be more stable and better at conserving energy (or at least not drifting wildly) compared to unconstrained black-box dynamics nets.

Discrete Spatial Diffusion: Intensity-Preserving Diffusion Modeling

  • Authors: Javier E. Santos, Agnese Marcato, Roman Colman, Nicholas Lubbers, Yen Ting Lin
  • Publication date: 2025-03-03
  • Venue: NeurIPS 2025
  • Link: https://openreview.net/forum?id=kz3w2A2y0e
  • Github: https://github.com/lanl/DiscreteSpatialDiffusion
  • Key innovations / contributions:
    • Discrete-state diffusion for conserved quantities: Formulates diffusion as a continuous-time, discrete-state jump process that operates directly on discrete intensities / counts (not continuous Gaussian noise).
    • Strict intensity/mass preservation: Ensures mass (particle count / intensity) is preserved in both forward and reverse diffusion processes.
    • The foreward process is simply Markov jump random walk, the network aims to learn the velocity vector field for reverse process.

Physics-Informed Diffusion Models

  • Authors: Jan-Hendrik Bastek, WaiChing Sun, Dennis M. Kochmann

  • Publication date: 2024-03-21

  • Venue: ICLR 2025

  • Link: https://arxiv.org/abs/2403.14404

  • Github: https://github.com/jhbastek/PhysicsInformedDiffusionModels

  • Key innovations / contributions:

    • Physics constraints integrated into diffusion training: Adds a first-principles physics loss (e.g., PDE residual) to the diffusion objective so generated samples satisfy governing equations.

    • Only enforcing physics constraints can lead to a degenerate outcome: as long as the generated sample satisfies the governing equations, the model may collapse to a single (or very limited) solution, which defeats the goal of learning a distribution over plausible solutions.

    • To avoid this, the authors combine the standard diffusion (data) objective with the virtual physics likelihood:

    max⁡θ Ex0∼q[log⁡pθ(x0)]  +  Ex0∼pθ[log⁡qR(r^=0∣x0)].\max_{\theta}\ \mathbb{E}_{x_0 \sim q}\big[\log p_{\theta}(x_0)\big] \;+\; \mathbb{E}_{x_0 \sim p_{\theta}}\big[\log q_{R}(\hat r = 0 \mid x_0)\big].θmax​ Ex0​∼q​[logpθ​(x0​)]+Ex0​∼pθ​​[logqR​(r^=0∣x0​)].

    This is the key step in PIDM that unifies generative modeling with PDE satisfaction:
    - the first term encourages fidelity to the data distribution,
    - the second term pushes samples toward physically valid solutions.

Learning to Simulate Complex Physics with Graph Networks (GNS)（Deepmind）

  • Authors: Alvaro Sanchez-Gonzalez, Jonathan Godwin, Tobias Pfaff, Rex Ying, Jure Leskovec, Peter W. Battaglia

  • Publication date: 2020-02-21

  • Venue: ICML 2020

  • Link: https://arxiv.org/abs/2002.09405

  • Github: https://github.com/google-deepmind/deepmind-research/blob/master/learning_to_simulate/README.md

  • Key innovations / contributions:

    • The paper proposes Graph Network-based Simulators (GNS) as a single learning framework that can model fluids, rigid solids, and deformable materials, including their interactions, using the same graph-based neural architecture and training recipe.
    • State representation: each particle is a node with features (e.g., position, velocity, type/material flags), and edges connect nearby particles based on spatial proximity (e.g., radius graph / nearest neighbors). This encodes the physical prior that interactions are mostly local.
    • A standard Graph Network-based Simulator (GNS) step can be summarized as:
      • Encoder: Map raw node and edge attributes into latent embeddings.
      • Processor: Apply message passing repeatedly:
        Gm+1=GNm+1(Gm),m=0,…,M−1G^{m+1} = GN^{m+1}(G^m), \quad m = 0, \dots, M-1Gm+1=GNm+1(Gm),m=0,…,M−1
        and return GMG^MGM. (The paper emphasizes this repeated message passing.)

  • Decoder: Map the final latent node states to predicted dynamics quantities (often accelerations or velocity/position updates), then use a simple integrator to advance the system forward one step.

Learning Distributions of Complex Fluid Simulations with Diffusion Graph Networks

6 Some personal thoughts concerning the potentiel research focus

  1. First of all, we need to know what kind of dataset that we can obtain, is it real data captured by the sensors or simulated data generated by traditional numerical methods? What kind of scale are they? It contains millions of stars like Galaxy or several planets like the solar system? It affects how we model the problem, more of a n-body problem or a fluid dynamics problem.
  2. Secondly, what kind of tasks are we aiming at ?
    • Predict the exact orbits of the n-body movements: maybe sole neural networks architectures are not going to exceed the performance of traditional numerical methods (Symplectic integrator for Hamiltonian systems) since the error can easily accumalate during the prediction of longer time. Perhaps it is better to combine the traditonal methods(use it to predict the backbone of the trajectory) and neural network(whether Transformer or Diffusion) to predict the slight deviation during the process. And it is preferable to use physcis-informed architecture like GNN or Hamiltonian preserved network(Hamiltonian Neural Networks or E(n) Equivariant Graph Neural Networks).
    • At which level of time scale we want to generate the prediction ? If we want to generate the trajectore second by second, then I doubt if we are able to find a pure Neural Network that outperform traditional integrator because the attention or full connected GNN is of complexity O(N2)O(N^{2})O(N2), it can be very costy and meanwhile not accurate. On the contrary, if we set the time step longer, e.g. one year? Maybe the network can perform better.
    • Alternatively, we might be able to predict the possibility of a potential collison without calculating the exact trajectory(e.g. Predicting the long-term stability of compact multiplanet systems). We can actually learn the features/distribution of instable system based on a shorter period data.
  3. Lastly, we need to test whether traditonal time series model works on our problem, since the n-body problem is a Markov process. Strictly, we can predict the next state solely from the previous one. What we learn from the past(seasonality and fluctuation), are they of great importance? Maybe they are, because the orbits make the mouvement kind of periodical.
